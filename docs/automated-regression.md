# 流程自动回归与迭代约定

提交和PR由 `.github/workflows/mcp-regression.yml` 自动执行回归。测试使用虚构、确定性的结构化输入，不依赖GPT、腾讯云、Tunnel或真实个人材料。业务预期断言、流程覆盖、结构契约和生成图一致性共同检查，任何一步失败都会使工作流失败。

## 自动执行顺序

1. 在Node.js 22中按lockfile安装依赖。
2. 执行全部业务及真实MCP SDK接口测试，包括问答、材料选择、任务隔离、检查条件、恢复、修改失效及回放。
3. 从当前实际XState模型提取节点、连线和条件，运行对应场景，依据执行轨迹核对覆盖。
4. 核对已经审查的结构契约，检测新增、删除或改接的流程，以及问题选项、字段、检查项、证据归属、读取范围和规则参数的变动。
5. 检查已提交的25项任务图、第一阶段SVG/HTML图及可执行导出是否与实际运行配置一致。
6. 将覆盖摘要写入GitHub Actions任务摘要，保留JSON及Markdown报告；失败时也尽可能生成报告。

本地开发使用同一入口 `npm run test:regression --prefix app`。`npm test --prefix app` 本身也包含流程覆盖测试，单独跑常规测试不会绕过流程门槛。

## 覆盖的定义

第一阶段决策树从真实XState微步轨迹采集节点和跳转，从实际条件调用采集真假结果；第二阶段从真实任务事件执行及历史采集成功跳转，对确实被条件拒绝的事件记录失败结果。

当前范围包括第一阶段决策树和25项任务，共26张实例化流程图：205个节点、469条连线、222个可达条件结果。重复使用共用骨架的不同任务分别计算，确保每项配置都实际执行。全部要求100%覆盖；不是对含重试循环的所有可能路径或全部输入组合作穷举。

部分选项路由的最后一个条件，在选项校验及前面的分支排除后只能为真。测试根据实际问题选项和判断顺序给出可检查的证明，并在报告单列这些不可能的反例；不使用手工忽略清单。增加选项后证明会重新计算，不再成立的反例自动成为必须覆盖的分支。

独立规则样例还要求已配置的自动检查具备pass、fail、unknown输入样例。保额及日期等边界预期使用明确的测试常量，不从实现阈值自动生成“正确答案”。每项用户检查、文件检查、必须读取的部分、准备确认和模糊项都分别测试缺失时不能完成。

## 场景与图的对应

| 文件 | 维护内容 |
| --- | --- |
| `app/test/support/decision-scenarios.mjs` | 成人职业、资助、未成年人、同行与监护、多国、缺失答案、非适用情况和日期顺序的输入组合 |
| `app/test/support/task-scenarios.mjs` | 自查、上传、修正重试、换检查方式、各步骤返回修改、外部取得、草稿、完成重开、失效与回放 |
| `app/test/support/flow-suite.mjs` | 执行场景、独立业务断言、规则覆盖和结构契约比对 |
| `app/test/support/flow-coverage.mjs` | 从实际模型提取图、按真实执行记录汇总覆盖、报告缺失项 |
| `app/test/fixtures/flow-contract.json` | 已审查的流程结构和任务要求目录，防止删除要求后覆盖分母缩小却仍通过 |
| `app/test/flow-coverage.test.js` | 完整覆盖门槛及门槛自身的反例测试 |

报告中保留每个节点、连线、条件结果对应的代表性场景名，以及每项任务的接受/拒绝事件序列，可定位到具体缺口。输出位于 `app/.local/test-results/flow-coverage.json` 和 `flow-coverage.md`，不会提交个人信息或连接生产数据。

## 迭代时如何适配

- 业务预期、图结构不变的重构：原回归必须直接通过。
- 新增节点、事件或条件：先增加有明确目标节点及成功/拒绝预期的场景。仅更新图或契约不能填补未执行的路径。
- 有意删除或改变需求：修改相应业务测试，并审查结构契约差异；不能仅因剩余路径达到100%就认定改动正确。
- 有意完成变更后，运行 `npm run test:flows:update-contract --prefix app` 更新契约。该命令先要求场景与覆盖通过，CI中禁止使用。
- 运行 `npm run task:graph --prefix app` 更新任务图，第一阶段变动时用 `npm run decision:graph --prefix app` 更新决策图，随后完整回跑 `test:regression`。场景、契约、配置及图作为同一变更提交。
- 新共用流程、嵌套/并行机器等超出当前适配器范围的结构会明确失败，需要扩展测试适配，不会静默跳过。

测试中刻意加入未覆盖的暂停节点及连线，验证门槛会失败；也验证改接目标、删除检查、删除条件和新增问题选项均能被发现。这些反例用于防止测试机制退化为只检查文件是否存在。

## 验证范围

这套流程验证结构化输入后的业务执行、条件、协议及状态持久化。GPT是否正确理解自然语言、是否正确读取真实附件，以及宿主是否真正显示页面，不能由状态机覆盖率证明；这些是独立的客户端或模型评测范围。
