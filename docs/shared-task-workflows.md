# 材料任务的共用流程与执行

当前实现覆盖冰岛清单中的25种任务 ID；一位申请人只得到决策树命中的材料，不是所有人都要准备25项。任务清单仍由第一阶段决定，第二阶段通过相同的 start_task 和 advance_task 接口消费任务。

## 任务身份与共用边界

每个任务以 `taskProgress[taskId]` 独立保存版本、模型指纹、revision、节点、完整数据、检查方式及执行历史。共用流程不会共用用户进度。既有申请表和护照的版本及配置指纹保持，历史进度不批量改写。

- `app/src/tasks.js` 是公共 XState 执行器：新建、读取、事件跳转、条件检查、保存前验证、版本冲突、失效处理及回放。
- `app/src/task-definitions.js` 是任务注册表：加载任务定义及流程配置，以 taskId 找到材料的配置、策略和机器；历史任务没有 taskId 时按已有版本识别。
- `app/config/task-workflows.json` 提供 `collect-v1` 和 `draft-v1` 两个可复用骨架。
- `app/config/tasks/iceland-materials-v1.json` 配置新增23种材料的要求、取得方式、检查问题、读取范围、字段、模板及规则。
- 申请表保留独立的原表流程配置；护照保留专用日期条件和最小个人信息结构，跳转复用材料检查骨架中与旧版一致的部分。注册时核对共用跳转与旧版定义一致，不能在维持旧指纹时静默改变旧流程。
- `app/src/task-policies.js` 提供可复用的日历日期、行程覆盖、最低金额和逐日条目核对。检查条件由代码执行，GPT 检查提示不代替确定性规则。

机器按任务定义实例化并缓存，条件由该任务的目录及策略生成；没有为每项材料复制一套状态保存和跳转代码。

## 两个共用流程

### collect-v1 材料准备与检查

说明要求并选择方式 → 用户自查或等待上传 → 检查与处理问题 → 用户确认材料已准备好。用户尚未取得材料时，可进入“取得或整理材料”，按任务指引外部办理，回来后继续检查。

外部办理只是引导与等待状态，不代表服务执行了购买、预订、付款、公证、认证或出具证明。原表没有明确的事项保留核实问题，例如担保人对账单期间、未成年人的资金安排、不同监护人所在地的证明形式。

### draft-v1 填写指引与材料草稿

整理字段并生成HTML → 用户完善、填写或交由出具方办理 → 选择自查或上传 → 用户确认完成。已有真实材料可以直接进入检查，不强制先生成草稿。

用于逐日行程、在职证明、学校证明和担保函。只有已确认信息被预填；未知项显示说明，不能由旅行日期推定单位或学校已批准准假。行程按已确认日期展示逐日网格，未知的地点、安排、交通、住宿不填造。单位或个人需要签署、盖章或正式出具的材料仍由真实出具方完成。

HTML使用共用模板 `app/public/templates/material-guide.html` 和各任务字段、标题、取得指引配置。申根原表继续使用原表编号的专用渲染。需要不同版式时可添加渲染模板，不改变任务实例与检查机制。

## 配置差异

| 配置 | 含义 |
| --- | --- |
| id、version、workflow、policy | 任务身份、版本、共用流程与特殊条件策略 |
| source、requirements、acquisition | 来源、材料要求及如何取得 |
| fields、document | 结构化字段目录、预填模板类型和标题 |
| checks | 各检查项的ID、标签、自查问题、提示、证据来自文件还是用户本人 |
| requiredCoverage | 上传辅助检查必须覆盖的文档部分，如身份证正反面、往返订单 |
| reviewInstructions | GPT 实际读取文件时的任务专用提示 |
| rules | 日期覆盖、金额下限、行程条目等已注册规则及参数 |

新增同类型任务时主要增加任务定义；有新的条件计算才扩展策略函数。需要额外节点时可以增加流程配置或使用独立机器。新增一种材料还须在第一阶段决策树适当位置引用其任务 ID，否则不会出现在申请清单。

新增任务的指纹包含其定义和实际共用流程；变更已发布流程需发布版本并明确处理进行中的任务，不能原地改写旧规则来解释旧历史。

## 统一数据与检查

新增材料使用完整快照：fields、checks、prepared、confirmedDetails、rows、review。只有逐日行程接受 rows，其余任务拒绝行程条目。任务字段及检查ID不在当前目录中时拒绝，不允许把另一材料的数据误写入本任务。

- 自查：检查项全部由用户明确确认，prepared 为 true。无需上传、无需提供个人字段，用户可检查外部准备的真实文件。
- 辅助检查：GPT实际读取后报告 documentRead、coverage、checks 和 findings；文件检查项在 review.checks，通过照片不能确认的项目在 data.checks 由用户本人核对。读取范围齐全、没有未解决的错误或模糊项、用户确认提取结果及材料准备好后才能完成。
- 日期、金额或行程条目的已知失败不能被勾选覆盖；缺少用于自动核对的数据显示未知，不冒称自动通过。自查或实际读取报告仍可提供相应的人工检查结论。
- 修改已检查内容先 EDIT，清除旧检查和完成确认；重试上传清除旧报告和确认。问答变化使任务重新核对。各次记录保存回放所需的行程日期。
- MCP 保存结构化检查报告，不保存原始聊天附件；辅助检查不等同于官方审批或文件真实性鉴定。

## 图与测试

运行 `npm run task:graph --prefix app`，生成[全部25种材料与流程索引](material-task-workflows.md)及各任务的实际 XState 图。运行 `npm run task:replay --prefix app -- APPLICATIONS_FILE APPLICATION_ID TASK_ID` 只读回放历史，不输出个人字段。

自动测试逐项验证全部材料的自查及辅助检查、覆盖范围、用户确认、任务隔离、并发版本、修改失效、规则和回放；浏览器测试桥覆盖代表性材料及原申请表、护照回归。真实宿主中的自然语言引导及附件阅读仍需用户验收。当前配置依据已有冰岛清单，覆盖软件流程不代表已完成全部现行官方规则的审查。
