# Visa Helper 开发进度

更新日期：2026年10月21日。当前发布版本 `0.12.0`，首条路径为单人、中国居民赴冰岛旅游。用户已在新会话续接测试并确认指导网页成功打开；本次因暂无时间填表，填写与检查的人工验收暂缓。

## 已确定的产品方案

产品通过 ChatGPT 对话引导，材料清单和任务操作由 MCP App 展示。

1. **确定材料清单**：GPT 取得问题目录和选项，将逐次回答或一整段旅行计划整理成同一种结构化问答。每次提交完整答案快照，服务端从入口重新运行 XState 决策树，返回下一步动作；有缺口再追问，完成后展示清单。
2. **逐项准备材料**：清单每一项对应一个独立任务，拥有自己的 XState 流程入口、输入、步骤、分支和完成条件。任务允许暂停、恢复和修改；共用字段说明、模板及底层能力可以复用。当前覆盖清单中全部25种任务ID，由第一阶段筛选适用于单个申请人的任务。
3. **职责分工**：MCP 保存规则、结构化资料、版本、进度及执行历史；GPT 整理用户表达、解释和引导；客户端浏览器负责网页打开及页面操作。打开浏览器的请求已发送，不代表页面已经显示。

## 两类填表辅助

**静态 PDF 表格**沿用填写对照页方案：针对每份表预先维护 HTML 模板、字段对应关系和填写说明，需要时使用已确认资料预填，未知项展示说明，再返回网页链接。用户对照网页填写原 PDF 或打印手写；原表下载、自查和可选辅助检查继续作为任务步骤。

后续可以持续优化模板，让项目顺序、分组和版式逐渐接近原 PDF，降低对照成本。首版不要求完全还原版式，也不以直接编辑或生成已填 PDF 为前提。模板随对应的官方表格版本维护。

**官方网站在线申请**另设任务流程，由客户端浏览器打开官方页面，读取当前可用的页面状态，再结合已确认资料指导用户填写，或在客户端能力和授权允许时辅助操作。页面加载、账号登录及动态步骤需单独处理，不能用静态对照页代替，也不因 PDF 任务完成而视为已经实现。

## 第一项任务 申根申请表

流程为：原表下载与资料整理 → 逐项填写对照页 → 用户自行填 PDF 或打印手写 → 自查或自愿上传辅助检查 → 用户确认填妥和签字。

填写和检查是同一项材料任务的内部步骤，不拆成两项清单任务。此次暂缓检查只表示暂不验收该步骤，不跳过系统完成条件，也不把打开指导页视为任务完成。

- 原始 PDF 随时可下载，不要求先提供全部个人资料。
- 对照页按原表项目列出内容：已确认的信息显示填写值，未知项显示填写说明，不编造答案。用户仍填写原始申请表。
- 不上传也能完成：提供自查清单，由用户确认；愿意上传时，GPT 读取聊天附件并提交结构化检查报告，MCP 不接收原始附件。
- 保存时区分用户自查与辅助检查记录。修改资料会清除旧检查及完成确认，要求重新核对。
- 进入任务后默认收起完整清单，顶部显示进度，右上角“全部任务”可展开切换。

流程图见[申根申请表任务流程](task-workflow-graph.md)。

## 第二项任务 护照与旅行证件

2026年10月20日已按以下设计实现，真实宿主尚待验收。护照准备与检查是一个任务，用户可选择两条路径：

- **上传辅助检查**：用户自愿拍摄或上传护照，Agent 读取并检查；提取信息由用户核对。图片未覆盖或看不清的项目继续询问，不能当作已检查通过。
- **对话自查**：GPT 根据任务检查项提出问题，指导用户查看护照，用户检查后明确确认结果。允许不上传完成，不要求为自查提供无关个人信息。

两条路径汇合到用户确认护照及按清单要求的递交材料已准备好。系统分别记录辅助检查与用户自查结果；有未解决问题则保留待处理，不能将选择路径或上传文件本身视为完成。实际检查要求沿用经核实的材料规则。本次已核对 VFS 中国冰岛个人旅游清单第2项，按预计入境日检查签发年限、按离境后3个日历月核对有效期；空白页由用户本人确认。服务只接受签发日期、到期日期，不保存姓名、号码或原图。

任务交付可以是已准备好的实体材料及其确认记录，不要求每个任务都生成或上传一个电子文件。[护照任务流程图](passport-task-workflow-graph.md)。

护照验收入口：恢复原申请，打开“全部任务”，选择“护照／旅行证件”，分别尝试“不上传，自己检查”和“拍照上传，让助手检查”。本次扩展 advance_task 输入结构和工具说明，需载入更新后的工具定义；无需新建申请。

## 全部材料与共用任务流程

2026年10月20日完成任务执行器抽取，全部25种材料任务按ID注册；当前成人在职样例仍只展示适用的12项。所有实例分别保存进度、数据、版本、检查方式和历史，不能因共用流程而混用数据。

- 直接准备材料复用 collect-v1：说明要求、外部取得指引、自查或辅助检查、处理问题、确认完成。
- 行程、在职证明、学校证明和担保函复用 draft-v1：预填HTML与未知项说明，完善或取得正式材料后，进入相同检查分支。
- 申根申请表保留专用原表流程及渲染；护照保留日期策略和隐私字段限制，执行、保存及回放统一到公共引擎，原配置指纹不变。
- 原件、空白页、拍摄时间、正式出具及公证认证等图片不能独立证明的项目，由用户明确核对。缺少文件覆盖范围或有未读清的问题，辅助检查不能完成。外部办理只提供指引，不实际购买、预订或出具材料。
- 全部任务分别配置HTML字段、要求、取得方式、检查提示和问题、覆盖范围及规则。原表未明确的未成年人资金安排、担保人对账单期间、特殊公证形式保留核实步骤。

13个自动测试文件通过，逐项验证23种新增材料的两条检查路径及回放；真实Chromium测试桥验证照片、保险、行程和在职证明，并回归原表与护照。真实宿主对新材料的自然语言引导和附件读取仍待验收。代码与配置说明见[共用任务架构](shared-task-workflows.md)，全部任务图见[材料任务索引](material-task-workflows.md)。

## 独立填写对照页的打开约定

MCP 在整理资料或等待填写阶段返回 `nextAction.type: open_url`，含预填网页 URL、到期时间和右侧位置提示；原业务步骤保存在 `taskAction`。其他任务步骤也可从模型可见的 `guidePresentation` 读取链接。

页卡的“让助手打开填写对照页”按钮通过当前聊天交接给 GPT。GPT 读取任务取得链接，再调用客户端浏览器工具；无法打开时，将可点击链接交给用户。卡片另提供普通网页链接及 HTML 下载。

临时网页入口使用已授权的腾讯云公网 IP 加端口，仅提供带随机令牌的只读对照页，不开放 MCP。链接有效期 15 分钟，资料或任务版本变化及服务重启会使旧链接失效，重新读取任务可取得新链接。

**2026年10月20日用户确认：新会话续接测试后，指导网页已成功打开。** 先前“仅提示已请求而未打开”的阻塞不再作为当前待办；本次用户未填写原表，检查与最终完成仍待人工验收。该反馈确认页面打开结果，不代表已逐段审计客户端内部工具调用。
