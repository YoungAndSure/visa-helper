# 冰岛旅游签证：问答决策树与材料任务队列

> 状态：用于申请准备和流程测试；材料规则尚待按现行官方要求复核。
>
> 唯一材料依据：用户提供的《VISA DOCUMENT CHECKLIST – TOURISM / 签证材料审核表 – 个人旅游》，PDF 创建于 2025-03-06，共 4 页。下文的编号对应原表第 1–13 项。正式服务真实申请人前，须按 [来源核对记录](iceland-source-audit.md) 复核当前官方版本、受理地点和规则。

## 1. 两个阶段

**第一阶段：确定任务。** 用户通过对话回答决策树中的问题。MCP 服务端根据已确认的答案，生成这位申请人的材料任务队列。这个阶段只决定「需要准备什么」，不负责收集、填写或生成文件。

**第二阶段：完成任务。** 用户从队列中逐个进入材料处理流程。每个任务对应一个要准备的文件；处理流程可以复用，例如上传并核对现有文件、指导用户取得第三方证明、辅助填写表格或生成行程文件。任务完成时关联一个最终文件。具体处理方式后续单独设计，不写进决策树。

用户体验按以下顺序展开：

1. **对话启动**：用户表达申请意图后，ChatGPT 调用 `create_application`。简短说明可跟随提问或直接描述整段计划。缺少答案时调用 `ask_next_question` 实际请求原生问题框，不打开 MCP App 网页。使用官方 MCP 多轮请求与 OpenAI 表单 SDK；当前原生表单测试入口是 ChatGPT Work 网页或桌面端。连接不支持时明确提示回退到普通对话，不能只靠提示词宣称会弹框。
2. **推进决策树**：用户逐题回答时，ChatGPT 把答案交给 `submit_answers`，由 MCP 保存并返回下一题。用户一口气说一段时，ChatGPT 根据问题目录提取明确的事实，代用户回答并继续调用接口；服务端可一次接收多个答案，运行到缺少必要信息的位置才停止。
3. **补充分支问题**：ChatGPT 优先使用对话中用户已经明确给出的信息，不能重复询问；没有答案时再问用户。服务端只进入适用的职业、未成年和多国行程分支。不能只承认「已保存」就结束问答。
4. **澄清不确定项**：日期含糊、答案矛盾或路径不明确时先在对话中澄清。未回答不等于否；不由 ChatGPT 自行补齐缺失条件或编造清单。
5. **叶子节点展示任务队列**：服务端返回 `tasks_ready` 和调用 `show_material_checklist` 的下一步，ChatGPT 随即调用，首次加载 MCP App 材料工作台，显示适用文件任务。工作台自动接收或读取当前申请，不要求用户再次创建或输入 ID 恢复。聊天只用一句话指引点击材料开始，不再复制完整清单或输出长篇说明。
6. **逐项完成任务**：用户从队列选择任务，进入该材料的独立处理流程；完成后把文件关联回原任务。更改分支答案时重新计算队列，并提示新增、移除及需复核的任务。
7. **递交前总览**：按原表顺序展示已完成、待处理及需人工确认的任务。第 3–4 页的签字／补件须知是递交阶段事项，不在材料筛选时误当成文件任务。

首版固定为**一位申请人对应一份申请和一份个人清单**。同行者的申请不进入本轮流程。

## 2. 问题树与材料分支

| 问题组 | 一次展示的问题 | 对清单的影响 |
| --- | --- | --- |
| 基础 A：路径 | 国籍；是否居住中国及拟递交城市；是否为旅游；是否还去其他申根国家及各国停留日期 | 决定是否进入本模拟路径；多国行程触发第 5 项的跨国交通材料，并提示核对冰岛是否为主要目的地。递交城市不从这份 PDF 推断具体受理中心。 |
| 基础 B：行程与申请人 | 首次进入／离开申根区的日期；出行时是否未满 18 岁；同行人员 | 日期供第 2、4、7 项检查；年龄决定进入成人或未成年人补充组。 |
| 成人 C：职业 | 在职、退休、无业？ | 第 11 项进入对应子分支。这里不能只问「是否有工作」，否则无法区分退休与无业。 |
| 成人 D：无业时 | 已婚／单身／离异／丧偶？旅行费用及日常收入来自哪里？由配偶、其他担保人还是本人承担？ | 已婚且依赖配偶、单身／离异／丧偶有固定收入、非配偶担保分别对应原表第 11 项的不同材料；回答不吻合原表时标为人工确认。 |
| 未成年 E | 是否在读？与谁同行：独自、一位家长、双方家长或其他监护人？监护关系如何证明？相关家长／监护人是否在中国？ | 第 13 项的在读证明、亲属／监护关系证明及按同行情形确定的出行同意文件。原表没有说明所有非典型家庭结构的处理办法，不能自行推断。 |
| 多国 F | 国家间使用飞机、火车还是汽车？相应预订情况？ | 第 5 项增加适用的申根境内交通预订。 |

问答全程在 ChatGPT 对话中完成，自建 MCP App 不承载问卷。无论逐题回答还是整段描述，都使用同一套决策树状态和答案接口。MCP 的返回值始终明确下一步，最终才交接给材料工作台。

### 决策树如何落到 MCP 服务端

从审核表抽取的每个条件成为一个明确的判断节点，引用所需问题和原表条目。问题组、停止条件和任务条件放在版本化 JSON 配置中，由开源 `json-logic-js` 求值。MCP 返回 `nextQuestion`、`pendingQuestions`、`questionCatalog` 和 `nextAction`；ChatGPT 负责理解用户原话并提交明确的结构化答案，MCP 保存后重新运行规则，直到下一处信息缺口或叶子节点。ChatGPT 不能自行增加材料条件或跳过树中必要的问题。叶子节点的完整清单放在工具结果 `_meta.application`，仅供工作台显示；模型收到清单数量和下一步动作，避免重复倾倒清单。

本表至少包含以下分支：

```text
中国居住者赴冰岛旅游？
├─ 否／无法确定 → 不生成本路径清单；说明待核实条件
└─ 是
   ├─ 成人 → 在职／退休／无业
   │           └─ 无业 → 婚姻状态、收入及担保人类型
   └─ 未成年人 → 在读及监护关系、独自／单方家长／双方家长同行

以上分支确定第 11 或 13 项；另根据多国行程追加第 5 项的境内交通材料。
路径走完后，将第 1–10 项中适用的共通文件任务与条件文件任务合并，得到唯一的个人任务队列。
```

从用户视角，每组完整答案都落在一片「叶子」上，叶子就是这位申请人的文件任务队列。实现时不预写所有组合的完整队列，而是由共通任务和条件任务合成叶子：年龄／职业、多国行程等条件彼此独立，预先枚举所有组合容易重复和漏改。每个任务要记录命中的条件和 PDF 条目，方便解释「为什么有这一项」。多个条件命中同一个文件时只生成一个任务。

例如「中国公民、居住中国、冰岛单国旅游、成年在职」得到第 1–10 项中适用的共通材料加第 11 项在职材料；若改为多国行程，第 5 项增加境内交通材料；若改为未成年人，仅重新计算受年龄与监护条件影响的材料。未回答的条件保持未确定，不进入任何最终叶子。

### 从新 checklist 生成问题树

用户提供新的 checklist 后，先提取每条材料的适用条件、所需文件、例外和出处；再归并重复条件，形成最少必要问题及其可选答案；随后检查各答案组合是否能得到明确结果，以及是否存在矛盾、空白或无法判断的分支。生成的是**待审核的规则配置草案**，人工核对原文后才发布到 MCP 服务端。PDF 没写清楚的情况标为待核实，不由模型填空。每次发布新增配置版本并切换 `active.json`；旧申请保持原版本，旧配置文件保留，不原地修改。

### 路径出口

- 非旅游目的（例如志愿活动）不套用旅游清单。原表第 12 项虽列出志愿活动邀请函，但应另建路径核对；本模拟在此停止个性化清单。
- 非中国国籍、非中国居住地、冰岛并非应受理目的地，或行程条件无法判断时，先显示需要核实的问题；不套用面向中国护照持有人居住中国的模拟路径。
- 签证是否必要、具体受理中心及官方递交办法不由这张材料表单独确定；模拟时将其列为正式申请前的核对点。

## 3. 原表到文件任务的映射

原表编号用于追溯依据，不等于任务编号。原表第 11 项的「雇主营业执照复印件」和「在职证明」是两个文件任务；第 13 项的学生证、学校证明和关系公证书也分别成任务。同一任务可以复用后续的材料处理流程。

| --- | --- | --- |
| 1 | 路径成立 | 统一申根申请表；协助整理已确认字段、检查打印与申请人签名。 |

| 4 | 路径成立 | 旅行医疗保险；核对覆盖全部申根停留期及原表所列最低保额，并关注离境航班和时区。 |
| 5 | 路径成立；多国时加子项 | 往返交通预订；若前往多个申根国家，补充相应的境内交通预订。 |
| 6 | 路径成立 | 逐日旅行行程；可从用户确认的日期与地点生成草稿，由用户核对。 |

这里的「路径成立」仅指**按所附 PDF 进行模拟的旅游路径**。原表第 10 项和第 13 项没有完整说明未成年人的资金安排；遇到空白应显示待核实，不补造要求。

## 4. 两阶段之间的交接

第一阶段输出的是有顺序的任务队列。每个任务至少包含：稳定的任务 ID、文件名称、对应的原表条目、命中的条件、原始要求、建议处理流程类型，以及「待处理／待核实」状态。它不包含已生成文件，也不预设用户一定要上传或自动生成。

第二阶段逐个消费任务。每个任务的目标是关联一个最终文件，并记录完成状态；如果原表还要求出示原件、打印或签字，这些作为该文件的递交说明保留，不误写成「系统生成了原件」。文件如何取得、填写与检查属于后续独立流程。

## 5. 模拟申请的验收场景

先使用虚构人物完成第一阶段：**中国公民、居住中国、成年在职、仅赴冰岛旅游**。用户一次回答基础问题与在职分支，系统生成第 1–11 项中适用的文件任务，其中营业执照复印件与在职证明是不同任务；不出现第 12、13 项。修改为「无业、由非配偶担保」后，任务队列相应变化。第二条短场景验证「未成年人仅随一位家长出行」能出现第 13 项的条件任务。

第一阶段跑通后，再选一个任务设计和验证第二阶段的材料处理流程。模拟全过程使用虚构资料，不提交官方申请。
