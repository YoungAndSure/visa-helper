# 本地与远端审核、文件脱敏设计（v1）

## 核心划分

材料审核不按“简单规则 / 复杂规则”划分，而按规则是否需要用户隐私划分：

- **本地审核**：规则需要姓名、证件号、出生日期、账户持有人等原始隐私，必须在浏览器本地执行。例如跨材料姓名一致性、证件号一致性、是否混入他人材料。
- **远端审核**：规则不需要知道用户真实身份，使用脱敏后的文件、国家 Checklist、知识库和后端模型执行。例如材料是否满足格式要求、证明力度、风险提示和开放式语义判断。

本地规则是明确、有限、可插件化维护的规则集合，不承担全部审核。远端模型负责本地固定规则无法穷举的完整审核，但它永远不应收到原始隐私材料。

## 完整流程

```text
选择本地文件夹
  → 本地识别/预处理（PDF 文字层、OCR、图片基础信息）
  → 本地审核（仅运行必须使用原始隐私的规则）
  → 本地隐私识别（PDF/JPG 全页视觉识别并自动画框）
  → 用户在原文件视觉副本上检查、补充手动涂抹
  → 将黑色遮挡烧录进新的 PDF/JPG，移除 PDF 文字层、批注和元数据
  → 用户逐份确认脱敏副本
  → 只发送匿名编号和脱敏后的 PDF/JPG
  → 后端 Agent 结合 Checklist、知识库和模型运行远端审核
  → 生成最终报告
```

原文件始终不修改。页面中看见的遮挡坐标与最终文件使用同一份数据，不能只用 CSS 或 PDF 覆盖层制造“看起来被遮住”的效果。

## 为什么仍然需要两段审核

如果先把姓名和证件号全部擦掉，后端就无法判断护照、户口本、银行流水是否属于同一申请人；如果把原件直接发送给后端，又破坏了隐私边界。因此必须先在本地完成依赖真实身份的交叉核对，再发送脱敏视觉文件进行完整的远端审核。

前端不需要判断远端规则是否“已经完备”，也不根据规则猜测某页是否值得发送。支持的 PDF/JPG 默认全部生成脱敏视觉副本，以保留版式、印章、照片、签字位置和其他非文本证据。

## 第一版文件支持

- PDF：逐页本地渲染，OCR 自动识别常见文本隐私；用户可补画；确认时逐页栅格化并重建新 PDF。
- JPG/JPEG：本地解码，OCR 自动识别常见文本隐私；用户可补画；确认时导出新的 JPG。
- 其他格式：当前标记为不支持，不允许作为已确认安全材料发送。后续根据实际规则反推需要新增的格式。

自动识别第一版覆盖邮箱、中国大陆手机号、身份证号、长银行账号、常见护照号，以及带姓名、地址、出生日期标签的内容。OCR、正则和版面判断都可能漏检，因此人工确认是强制安全门。头像、签名、二维码等对象检测不在第一版自动能力内，用户需要手动画框。

OCR 引擎、中文/英文语言包、PDF 渲染和重建组件都随应用本地提供。处理用户材料时不调用 CDN、远程 OCR 或远程模型。

## 发送协议

每个原文件对应一个匿名安全文件对象，不发送原文件名、本地路径、OCR 原文或编辑器坐标：

```json
{
  "schema_version": "privacy-files/v1",
  "country": "IS",
  "visa_type": "schengen-tourism",
  "privacy": {
    "processed_locally": true,
    "raw_files_uploaded": false,
    "user_reviewed": true,
    "redaction_engine": "browser-ocr-manual-v1"
  },
  "materials": [
    {
      "material_id": "material-001",
      "source_ref": "local-file-001",
      "kind": "pdf",
      "media_type": "application/pdf",
      "sanitized_file": {
        "media_type": "application/pdf",
        "content": "data:application/pdf;base64,...",
        "size": 123456,
        "page_count": 2,
        "redaction_count": 5
      },
      "review_status": "ready"
    }
  ]
}
```

当前用 Base64 data URL 放进 JSON 作为前后端传输封装；语义上发送的是重建后的文件副本，而不是抽取后的文本 JSON。后续可改为 multipart 或对象存储上传，不改变匿名材料和隐私边界。

## 安全约束

- 原始 `File` 只保存在浏览器本地会话和 IndexedDB 恢复区，不进入请求；
- 发送对象不包含原文件名、目录路径、OCR 原文和打码坐标；
- PDF 必须栅格化重建，避免遮挡下仍保留可复制文字、表单、批注或元数据；
- 任何一次手动修改都会撤销该材料的确认状态，并要求重新烧录；
- 所有材料确认前，远端审核按钮保持禁用；
- `/material-audit/run` 等敏感接口不记录请求正文。
