## 一级审核：由真实规则反推本地识别能力

状态：基础 PDF 文字层提取和双 Worker OCR 已实现；高级识别能力待收集真实规则后实施。

### 已确定原则

- 基础 OCR 只用于扫描页和图片的文字可读性与隐私定位；暂不盲目接入表格识别、对象检测、
  图片描述或本地视觉模型。
- 先收集并结构化真实的签证材料审核规则，再根据规则需要的证据决定实现哪些识别能力。
- 本地识别/预处理模块与一级审核规则模块保持解耦，只通过统一 Document Context 交互。
- 每条插件规则从完整 Context 中自行寻找候选材料、执行检查并输出标准结果。
- 原始文件和一级审核所需的隐私信息必须留在浏览器本地，不发送给后端。

### 后续实施顺序

1. 收集各国家、签证类型的官方 Checklist 和真实审核规则。
2. 为每条规则记录所需证据，例如文字字段、版面结构、图片对象、文件属性或跨文件一致性。
3. 判断这些证据能否通过现有 PDF 文字层、基础 OCR 和文本解析取得。
4. 对无法取得的证据，再选择性接入 MRZ、表格识别、字段抽取、对象检测或视觉模型。
5. 将新增能力封装为预处理适配器或规则共用工具，并写入统一 Document Context。
6. 为规则补充固定样本、预期结果和回归测试，再加入规则注册表。

### 规则调研记录模板

| 项目 | 内容 |
|---|---|
| 规则 ID | 例如 `passport.validity` |
| 国家 / 签证类型 | 规则适用范围 |
| 判断目标 | 需要判断什么 |
| 候选材料 | 规则需要从哪些材料中查找 |
| 所需证据 | 文字、日期、表格、印章、人像、MRZ 等 |
| 当前能否获取 | 可以 / 部分可以 / 不可以 |
| 待补本地能力 | 只填写规则确实需要的识别能力 |
| 预期结果 | pass / fail / warning / unavailable 等 |
| 来源 | 官方 Checklist、使领馆说明或经过验证的经验 |

相关架构说明见 `docs/local-level-one-audit.md`。
